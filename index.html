Trapping Rain Water: From O(n) Space to Two Pointers

Trapping Rain Water is a favorite hard question because the brute force is obvious and the optimal version needs one clean insight.

The insight

Water above index i equals min(maxLeft[i], maxRight[i]) - height[i], never below zero. Everything else is about computing those two maxima cheaply.

Version 1: prefix and suffix arrays

Precompute maxLeft from the left and maxRight from the right, then sum. O(n) time and O(n) space. This is a strong first answer.

Version 2: two pointers

Keep left, right, leftMax, and rightMax. Move whichever side has the smaller max, because that side's water level is already decided. O(n) time and O(1) space.

Version 3: monotonic stack

Push indices while heights decrease; when a taller bar arrives, pop and add the water trapped between the new bar and the bar below the popped one. Mention it if the interviewer asks for alternatives.

Test cases

[0,1,0,2,1,0,1,3,2,1,2,1] gives 6. Also try an empty array, a strictly increasing array, and a single valley. For timed practice on problems like this I use an AI coding interview assistant.
